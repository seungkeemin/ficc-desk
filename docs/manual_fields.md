# 수동 입력 7필드

자동 수집이 없는 필드다. 매일 손으로 넣는다. 화면의 인라인 입력을 쓰거나,
`PUT /api/observation` 으로 직접 넣는다.

이 문서에 적힌 URL 은 전부 2026-08-12 에 실제로 열어서 값이 보이는 것을 확인했다.
값을 확인하지 못한 항목은 **확인 필요** 로 남겼다 — 추측한 주소를 적지 않는다
(CLAUDE.md 불변 규칙 3).

관측 예시는 전부 **2026-08-11 자** 화면이다. 값 자체가 아니라 "화면의 이 자리에
이런 모양의 숫자가 있다"를 확인하기 위한 것이다.

> **미수집을 0 이나 추정치로 채우지 않는다.** 못 찾았으면 비워 둔다.
> "값이 없다"와 "값이 0이다"를 섞으면 시계열이 조용히 망가진다 (CLAUDE.md 1).

## `irs_1y` · `irs_3y` · `irs_5y` — KRW IRS 1년 / 3년 / 5년

**URL** <http://www.smbs.biz/Exchange/IRS.jsp>
(서울외국환중개 → 파생상품시장 → IRS. https 는 인증서가 `m.smbs.biz` 용이라
`www` 로는 붙지 않는다. **http 로 연다.**)

**어느 셀** 페이지 아래쪽 `IRS RATE` 표. 표 제목 옆에 기준일이 `2026년 08월 11일`
형식으로 붙어 있고 `(단위 : %)` 라고 쓰여 있다. 행이 기일물(`1Y` `2Y` `3Y` …),
열이 `Receive` / `Mid` / `Pay` 다.

- `irs_1y` ← `1Y` 행의 **`Mid`** 열
- `irs_3y` ← `3Y` 행의 **`Mid`** 열
- `irs_5y` ← `5Y` 행의 **`Mid`** 열

Receive/Pay 가 아니라 Mid 를 쓴다. 본드-스왑 스프레드(`bond_swap_3y`)가 국고채
민평 수익률과 비교되는 값이라, 한쪽 사이드를 쓰면 스프레드에 매수/매도 마진이
섞여 들어간다.

**관측 예시 (2026-08-11)** 1Y 3.4650 · 3Y 3.8500 · 5Y 3.9750
(같은 행의 Receive/Pay 는 3.4750/3.4550 처럼 Mid ±1bp 로 붙는다.)

**언제 확정되나** 2026-08-12 00:45 KST 에 열었을 때 최신 표가 `2026년 08월 11일`
자였다. 즉 전 영업일 마감치는 확실히 올라와 있다. **당일 값이 몇 시에 붙는지는
확인 필요.** 3주 뒤 회차 축소를 검토할 때 16:30 회차와 23:30 회차의 값을 비교하면
알 수 있다 — 16:30 에 이미 당일자가 보이면 그때 확정되는 것이고, 23:30 에만
보이면 저녁 회차가 필요하다는 뜻이다. **그때까지는 23:30 이후에 입력한다.**

## `ndf_1m` — 1개월 NDF

**URL 확인 필요.** 1개월 NDF **아웃라이트 환율**(원 단위 환율 수준)을 무료로
보여주는 화면을 찾지 못했다.

찾아본 것과 결과:

| 열어 본 곳 | 결과 |
|---|---|
| <http://www.smbs.biz/Exchange/NDF.jsp> | 상품 설명(거래통화·거래시간·결제방법)만 있고 호가가 없다 |
| <https://www.investing.com/currencies/usd-krw-forward-rates> | `USDKRW 1M FWD` 는 있으나 **선물환 포인트**(Bid −175.0000 / Ask 25.0000)이지 아웃라이트가 아니다 |

`field_def` 상 `ndf_1m` 의 단위는 `krw` — 1,4xx 대의 **환율 수준**이지 포인트가
아니다. 위 두 곳의 숫자를 그대로 넣으면 단위가 다른 값이 시계열에 섞인다.

**결정이 필요한 것** (다음 작업 전에 하나 고른다)

1. 현물 `usdkrw` + `swap_point_1m`/100 으로 계산한다 → 그러면 이건 파생값이므로
   저장하지 않고 조회 시 계산해야 한다 (CLAUDE.md 2). 필드를 없애는 쪽이 맞다.
2. NDF 아웃라이트를 그대로 주는 화면(유료 단말 포함)을 찾는다.
3. 이 필드를 비활성(`active = 0`)으로 내린다.

정할 때까지는 **비워 둔다.** 대충 채우지 않는다.

## `swap_point_1m` — 스왑포인트 1개월

**URL** <http://www.smbs.biz/Exchange/FxSwapUS.jsp>
(서울외국환중개 → 외환시장 → F/X Swap. 여기도 **http**.)

**어느 셀** 페이지 아래쪽 `F/X Swap POINT` 표. 기준일이 `2026년 08월11일` 형식으로
붙어 있고 `(단위 : 전(KRW))` 이라고 쓰여 있다. 열이 기일물(`1M` `2M` `3M` `6M` `1Y`),
행이 `Bid` / `Offer` 다. → **`1M` 열**.

**Mid 가 없다.** 화면에 Bid 와 Offer 두 줄뿐이라 어느 쪽을 넣을지 규칙을 정해야
한다. 정하고 나면 이 줄을 고쳐서 확정된 규칙만 남긴다.

- Bid/Offer 의 중간값 `(Bid + Offer) / 2` — IRS 를 Mid 로 넣는 것과 일관된다
- 또는 Bid 고정 — 화면 값을 그대로 옮기므로 옮겨적기 오류가 없다

**관측 예시 (2026-08-11)** 1M Bid −175.00 / Offer 25.00 (전). 중간값이면 −75.00.
스프레드가 200전(=2원)으로 넓다 — 이 표는 체결가가 아니라 호가 범위다.

같은 날 <https://www.investing.com/currencies/usd-krw-forward-rates> 의
`USDKRW 1M FWD` 도 Bid −175.0000 / Ask 25.0000 으로 **같은 값**이었다. 한쪽이
멈췄는지 의심될 때 교차 확인용으로 쓴다.

**언제 확정되나** IRS 와 같다 — 2026-08-12 00:45 KST 에 최신 표가 `2026년 08월11일`
자였다. **당일 값이 붙는 시각은 확인 필요.** 23:30 이후에 입력한다.

> 헷갈리는 화면: <http://www.smbs.biz/ExRate/FutureExRate.jsp> (통화선도환율)에도
> `SWAP POINT` 행에 `1개월물` 이 있다. 이건 **월말 회계평가용 월 1회 고시**이고
> 단위도 전이 아니라 **원**이다 (2026-07-31 기준 −0.46). 이 필드에 넣지 마라.

## `dxy` — 달러 인덱스

**URL** <https://www.marketwatch.com/investing/index/dxy>

**어느 셀** 페이지 상단 종목 헤더 `U.S. Dollar Index (DXY)` / `U.S.: ICE FUTURES U.S.`
바로 아래의 큰 숫자. 그 왼쪽에 `Last Updated: Aug 11, 2026 at 11:28 a.m. EDT` 와
`Delayed quote` 가 붙고, 오른쪽 블록에 `PREVIOUS CLOSE` 가 따로 있다.

- 아침 07:30 회차에 넣을 때 → **`PREVIOUS CLOSE`** (미국 전일 세션 종가)
- 장중 값을 참고로 볼 때 → 큰 숫자 (지연 시세)

**관측 예시 (2026-08-12 00:45 KST = 2026-08-11 11:28 EDT)**
현재가 99.82, PREVIOUS CLOSE 99.81.

**언제 확정되나** KST 기준 아침이면 미국 전일 세션이 끝나 있으므로, **07:30 회차
시점에 `PREVIOUS CLOSE` 를 그날의 전일 종가로 넣는다.** 화면에 세션 마감 시각이
표기돼 있지는 않다.

**주의** `market_observation` 의 `obs_date` 는 KST 관측일이다. 07:30 에 넣는 값은
미국 기준 전일 종가이므로, 다른 필드와 하루가 어긋난 채로 같은 날짜에 들어간다.
DXY 를 국내 지표와 나란히 볼 때 이 하루 차이를 잊지 마라 (SPEC 4-2 의 관측일
규칙과 같은 문제다).

교차 확인용: <https://www.investing.com/currencies/usd-krw-forward-rates> 우측
`Dollar Index` 도 같은 지수다 (같은 시각 99.740 — MarketWatch 와 지연 폭이 달라
소수점 아래가 다르다. **한 소스만 정해서 계속 쓴다.** 날마다 소스를 바꾸면
전일 대비 변화가 시세가 아니라 소스 차이가 된다).

## `kr_cds_5y` — 한국 CDS 5년

**URL** <https://www.worldgovernmentbonds.com/cds-historical-data/south-korea/5-years/>

**어느 셀** 페이지 최상단 `SOUTH KOREA - 5 Years CDS` 블록의 큰 숫자 (그 옆 `%` 는
1개월 변화율이지 값이 아니다). 바로 아래에 `Last Update: 11 Aug 2026 9:48 GMT+0`
이 붙는다. 같은 값이 페이지 중간 `Current CDS: 23.10` 에도 다시 나오므로 옮겨적기
전에 두 곳이 같은지 본다.

**관측 예시 (2026-08-11)** 23.10 bp. `Last Update: 11 Aug 2026 9:48 GMT+0`.

**언제 확정되나** 갱신 표기가 `9:48 GMT+0` = **18:48 KST**. 하루 한 번 갱신되고,
이 값은 그날치다. **23:30 회차 이후에 입력하면 그날 값이 들어간다.** 07:30 에
보면 전날 값이다.

**주의** 이 사이트는 JavaScript 로 값을 채운다. `curl` 이나 단순 HTML 조회로는
`----` 만 나온다 (실제로 그랬다). 브라우저로 열어야 값이 보인다 — 나중에 자동
수집을 붙일 생각이라면 이 사실이 먼저다.
